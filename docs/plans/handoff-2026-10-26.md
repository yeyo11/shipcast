## How work is done here

- **Verify only through Sluice's `verify`** (typecheck and test), never the commands in a shell; a
  commit needs a cached typecheck pass and a push a cached test pass.
- **Documents only through pando's `kb_add_document`.** It writes into the main checkout's `docs/`:
  copy the file into the branch's worktree, then restore the main checkout with
  `git checkout -- docs/<file>`. The main checkout runs production: it stays on `main`, clean.
- **One pull request per batch of changes**, opened by the agent; branch from a clean `main`, in
  `git worktree`s; stage files by name, never `git add -A`; Conventional Commits with the
  `Co-Authored-By` line. The owner merges, unless they ask the agent to.
- **Design is shown running before it merges.** A preview is a copy of the app on one local address:
  `SHIPCAST_APP_TLS=off`, its own throwaway Postgres restored from a backup with automation turned off,
  its own `SHIPCAST_KEYCHAIN_SERVICE` and the GitHub App's key by absolute path, started with
  `systemd-run --user`. A preview never issues or touches certificates (the keychain's TLS key is
  shared with production).
- **Deploy:** `pg_dump` into `data/backups/` first (gitignored), `git merge --ff-only origin/main` in the
  main checkout, `pnpm install`, `systemctl --user restart shipcast-app`, then
  `curl https://shipcast.josegarrido.dev/api/health` without `-k` and compare the table counts
  before and after. Migrations are additive; the owner's data is never lost.
- **Sub-agents** work in a worktree and branch each, are told to commit after every point (a session
  limit can stop them at any time) and are merged by the lead; their uncommitted work is saved as a
  patch in `data/backups/` before one is resumed. An agent resumed keeps its model: to change the
  model, start a new one.
- Everything technical is written in English; the chat with the owner is in Spanish. No secrets, no
  private details of the owner's install in this repository.
